## 1.2.1 MEMO Protocol：协议与网络底座

> **产品定位：MEMO 的协议与网络底座，定义存储、身份、验证、执行及结算的共同规则，为 Vault、Agent Gateway 和 Proof 提供基础能力。**

MEMO Protocol 组织用户、存储提供者、守护者和验证者之间的协作。用户提交服务需求；提供者按订单保存数据并响应证明；守护者参与匹配、挑战和修复协调；结算模块依据服务记录与验证结果分配费用。角色权限、证明窗口、算法集合和经济参数由版本化协议配置约束。

Protocol 提供可复用的网络能力与协作规则，模型、Agent 框架和应用编排通过上层接口使用这些能力。六层协议能力域、MEFS 节点网络、验证与结算流程共同支撑 Agent 状态的保存、接续和核验。

## 1.2.2 MEMO Vault：Agent 状态存在哪里

> **产品定位：用户可控的 Agent 状态存储与管理层，将 Memory、Task State、Checkpoint、Trace 和 Artifact 组织为可加密、可版本化、可迁移的状态对象。**

Vault 统一对象标识、命名空间、版本图、来源、授权引用和生命周期，并通过后端接口连接三种存储形态：

* **Local** 将加密状态与索引保存在用户或组织控制的设备中；
* **Hosted** 由托管服务承担资源调度、备份与运行维护，密钥控制通过用户密钥或组织 KMS 策略配置；
* **MEFS** 将加密对象交给去中心化存储网络，使用订单、冗余、修复和存储证明管理长期保存责任。

三种后端共享状态对象契约，存储位置与服务责任由部署配置选择。Gateway 校验每次受管访问的身份、委托和用途；密钥系统依据接收者和用途封装数据密钥；导出遵守对象权利、来源许可和接收方授权。

Vault 定义对象与状态语义，MEFS 定义去中心化存储责任。后端迁移通过 Memory Pack 保留逻辑对象、父版本图、来源和授权引用。`content_ref` 是稳定内容引用，定位映射记录物理位置；同一密文迁移只更新位置映射，原对象版本与摘要保持不变。重新加密或格式转换创建新对象版本，记录封装映射与转换回执，形成连续的迁移证据。

## 1.2.3 MEMO Agent Gateway：谁能做什么

> **产品定位：Agent 状态访问的统一策略入口，执行主体识别、Owner 委托验证、细粒度授权、请求调度与本地签名回执记录。**

Gateway 分别记录用户身份、Agent DID、执行实例与单次运行，校验 Owner 签署的委托，再按命名空间、操作、期限、用途、费用和外部动作范围执行策略。Agent DID 绑定身份签名公钥与执行实例；身份签名密钥更换时创建新实例和新 DID，通过签名连续性记录关联历史，并由 Owner 为新 DID 签发独立委托。

MCP、REST 和 SDK 接入同一策略与状态操作契约。经过受管入口的允许与拒绝请求均进入本地回执流程，持久化失败进入按 `operation_id` 关联的恢复队列，业务结果与回执状态分别返回。注册、Owner 绑定与访问委托是三个独立步骤，执行主体只有在有效委托和策略同时通过后才能访问相应资源。

## 1.2.4 MEMO Proof：如何证明发生过

> **产品定位：Agent 状态的证据组织与核验层，将访问、来源、运行、存储及外部声明关联到明确的对象、版本和业务操作。**

Proof 采集并聚合访问回执、审计根、对象承诺、Attestation、FileProof 与存储证明，为核验者提供证据范围、签发者、算法、时间窗口和验证入口。对象创建时记录已知 `proof_refs`；后续证明追加到按 `(object_id, version)` 索引的 Proof Registry，查询时合并展示，保持对象版本不可变。

各类证据对应明确命题。签名回执表达签发者作出的事件声明，Merkle 包含证明说明记录属于某个锚定批次，存储证明核验约定时间窗口内的保存责任。日志覆盖、事件真实性与业务成果符合性分别由相应规则核验，不能仅凭某一类证明推出全部结论。

## 1.2.5 MEFS：去中心化存储网络

> **产品定位：去中心化长期存储网络，通过存储订单、冗余、修复、挑战和证明管理加密数据的保存责任。**

MEFS 采用多副本、纠删码及 RAFI 风险感知故障识别组织可靠性机制。RAFI 按数据块风险设置差异化阈值，触发检查和修复；守护者依协议配置挑战提供者，挑战、证明与修复记录进入结算和责任判断。用户、提供者、守护者、订单、质押与结算共同构成 Vault 的去中心化后端。

Vault 适配器把状态对象的密文封装、内容引用及证明需求映射到 MEFS 存储订单，逻辑对象、命名空间、版本、来源与策略继续由状态层维护。MEFS 同时承担通用文件存储和 Agent 状态密文保存，两类负载共享网络职责并分别计量。

## 1.2.6 Data Wallet：用户身份、密钥与授权入口

> **产品定位：用户身份、数据密钥与授权策略的控制入口，管理数据访问权、Agent 委托、密钥封装与恢复配置。**

Data Wallet 使用身份与权限记录管理数据资产，为不同存储系统配置独立的数据加密密钥，并以 Reader 等角色表达访问范围。Owner 通过签名委托设置主体、资源、操作、用途、期限及预算；策略引擎据此自动处理请求。钱包提供委托查询与撤销、数据密钥轮换、状态导出和访问记录查询。

Data Wallet 管理用户控制配置，Gateway 执行每次访问判断，Vault 保存状态，Proof 组织证据。控制界面、策略执行点、密钥系统和审计服务通过可验证请求连接；撤销阻断后续受控访问和密钥发放，已经披露的明文仍由其接收环境控制。

## 1.2.7 Data Market：数据与状态资产交付

> **产品定位：数据与 Agent 状态资产的授权交易和交付层，将资产描述、用途许可、报价、结算、密钥发放及交付证据连接为完整流程。**

Data Market 通过 DID 关联身份、资产与访问权，以 MEFS 保存加密交付物，以智能合约和结算适配器记录必要的交易关系。Memory Pack、经验数据、Skill、训练数据集和成果按资产策略筛选；来源许可、敏感数据检测、授权范围和接收者资格通过后，生成限定用途、期限和范围的交付包。

普通个人记忆保持私有，只有 Owner 在签名策略中明确选定的对象才能进入资产流程。读取、训练、再分发、商业使用和所有权转移分别授权。支付完成后，Gateway 重新检查委托、策略及撤销状态，再按接收者密钥交付；支付状态、密钥发放和业务交付分别记录。

## 1.2.8 Meeda：数据可用性与存储证明

> **产品定位：数据可用性组件，主要提供存储性证明，通过链下数据保存、链上承诺、随机抽样和挑战，为 Proof 提供限定范围的可用性证据。**

Meeda 的数据路径将数据保存在链下，将 KZG 承诺登记在链上。Light Node 获取验证材料并执行核验，按协议规则对异常发起挑战。抽样数量、挑战窗口、保留期限、网络参数和奖励规则由版本化配置绑定，验证结果同时携带所用参数与时间范围。

Meeda 负责数据可用性与相关存储证明，Proof 负责跨证据类型的组织和核验。Meeda 通过证据适配器向 Proof 提交承诺、抽样及挑战结果，Proof 保留该证明的假设和适用边界。
