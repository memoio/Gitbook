# 2.1 MEMO Protocol：统一协议与网络底座

### 2.1.1 协议定位、网络角色与能力边界

{% hint style="info" %}
**产品定位：连接存储、身份、验证、计算、执行与结算的统一协议与网络底座，为 Agent 状态服务提供节点协作、可验证保存与结算规则。**
{% endhint %}

MEMO Protocol 是连接存储、身份、验证、计算、执行与结算的协议底座。它定义用户、提供者、守护者和其他网络节点之间的协作关系，为上层产品提供可复用的网络能力。守护者参与挑战，并按挑战结果及网络规则触发支付，将提供者收入与可验证的服务结果关联。角色权限、挑战周期、结算条件与服务范围写入版本化网络配置；节点在接单、挑战和结算前校验配置签名、网络标识与有效期。

| 角色        | 核心职责                | 在 Agent State Layer 中的延续 |
| --------- | ------------------- | ------------------------ |
| 用户        | 提交数据、支付存储或服务费用、掌控密钥 | 成为状态所有者与委托发起者            |
| 提供者       | 提供存储空间、保存数据、响应挑战    | 保存 Vault 进入 MEFS 的加密状态对象 |
| 守护者       | 订单管理、挑战、凭证与修复协调     | 继续支撑存储证明与网络治理            |
| 验证 / 合约组件 | 登记、挑战、结算与裁决         | 支撑 Proof 的锚定、验证和必要争议处理   |

Protocol 不替代具体模型和 Agent 框架，不直接定义业务流程，也不要求把所有运行内容放到链上。上层产品通过 Protocol 使用存储、身份、证明和结算能力。

### 2.1.2 六层协议与 Agent State Layer 的映射

MEMO Protocol 的六层描述网络能力域；Agent State Layer 按一次状态请求组织对象、身份、授权、存储、证据和受控处理职责。二者通过版本化接口映射连接：输入输出使用统一对象引用，身份与用途检查沿请求链传递，验证结果按明确命题回传。

| MEMO Protocol 六层 | 协议职责                     | 在 Agent State Layer 中的承接                    |
| ---------------- | ------------------------ | ------------------------------------------- |
| 数据存储层            | 数据保存、冗余、修复               | Vault 存储后端、MEFS、状态对象持久保存                    |
| 计算层              | TEE、算力与数据处理              | 授权后的算力平台、TEE、检索、脱敏与受控处理                     |
| 验证层              | 证明、挑战与验证                 | 存储证明、审计根、来源声明与运行证据                          |
| 执行层              | 合约、登记与结算                 | 链上锚定、状态登记、挑战、结算与必要裁决                        |
| 身份层              | User / File / Device DID | User DID、Data DID、Device DID、Agent DID 与委托链 |
| 智能层              | 接入、服务与组合                 | Gateway 策略执行、MCP / SDK 接入与状态服务              |

Protocol 六层解释网络能力域；Agent State Layer 六层解释状态请求中的协作职责。映射表保留两者的不同抽象层级，便于独立配置和核验。

### 2.1.3 Protocol 与 Vault / Gateway / Proof 的关系

一个协议底座与三个 Agent 产品分别回答以下问题：

| 层级                 | 回答的问题               | 主责                | 典型输出                             |
| ------------------ | ------------------- | ----------------- | -------------------------------- |
| MEMO Protocol      | 底层能力如何被网络提供和验证      | 协议、节点、存储、验证、执行与结算 | 网络服务、证明与结算能力                     |
| MEMO Vault         | 状态是什么、存在哪里、如何版本化和加密 | 对象、命名空间、版本、密钥与后端  | State Object、Version、Memory Pack |
| MEMO Agent Gateway | 谁在什么委托下能做什么         | 身份、策略、撤销、接入与回执    | allow / deny、Access Receipt      |
| MEMO Proof         | 某项访问、来源或存储事实如何核验    | 审计根、承诺、证明与验证接口    | Audit Root、Proof Pointer         |

典型调用关系是：Agent 经 Gateway 取得授权，Gateway 读写 Vault，Vault 可使用 MEFS；Gateway 和 Vault 产生的事实交给 Proof 聚合，底层网络与合约由 Protocol 支撑。
