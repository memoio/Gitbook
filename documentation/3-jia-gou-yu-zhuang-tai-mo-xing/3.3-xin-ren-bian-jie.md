# 3.3 信任边界

## 3.3.1 链上与链下边界

原则：链上只放承诺、根、证明结果与必要裁决；状态原文、密钥、授权判断和高频读写留在链下。Meeda 的 DA 设计把 KZG 承诺与聚合证明放在链上、blob 留在链下；验证配置绑定算法标识、参数集、网络标识、合约版本与挑战窗口，验证者按该配置核验对应数据批次。

| 类型      | 位置                            | 原因                          |
| ------- | ----------------------------- | --------------------------- |
| 状态原文    | 链下：Local / Hosted / MEFS，加密保存 | 隐私、低延迟、密钥轮换与大对象成本           |
| 授权判断    | 链下，由 Gateway 执行               | Agent 请求不能每次等待链上确认          |
| 访问回执    | 链下签名日志，先按策略本地保存，再异步导出或锚定      | 将请求处理与批量锚定解耦，保留可追溯记录        |
| 审计根     | 链上或公开验证系统                     | 对指定批次核验成员关系和内容一致性；不自动证明日志完整 |
| 存储承诺与证明 | 链上承诺 / 公开验证材料                 | 证明特定时间窗口内按规则保存              |
| 状态资产登记  | 链上，按实现对齐 ERC-7829             | 仅用于确权、交付或交易对象               |

状态资产登记不默认把所有个人记忆 NFT 化或公开化。回执批量锚定不应阻塞请求热路径。

## 3.3.2 原文、密钥、承诺与证明

以下六个概念分别表达内容、能力或证据，核验时不能互相替代：

| 概念          | 定义                                     | 可以说明                   | 不能说明                         |
| ----------- | -------------------------------------- | ---------------------- | ---------------------------- |
| 原文          | 实际状态内容，默认链下加密保存                        | 内容本身                   | 有 CID 不等于永久可用或已授权            |
| 密钥          | 按用途区分的密码学材料；内容加密密钥用于加解密，身份签名密钥用于主体控制证明 | 对应的解密能力或签名控制能力         | 持钥不等于取得业务用途许可；两类密钥更换不能混称     |
| Commitment  | 绑定明确算法、范围和内容版本的承诺对象                    | 指定范围内的一致性比较；对象示例覆盖密文封装 | 不是存储证明，不证明内容真实，也不保证重新加密后摘要不变 |
| Receipt     | 签发者对请求、决定和结果作出的签名记录                    | 签发者作出过相应事件声明           | 不自动证明事件真实发生、日志完整或任务验收通过      |
| Attestation | 主体针对对象或事件签发的声明                         | 某主体作出过特定声明             | 声明不等于事实本身真实                  |
| Proof       | 针对明确命题提供的验证材料                          | 指定命题在条件内成立             | 不能笼统证明 Agent 正确              |

每类证据明确绑定证明对象、发行者与验证者、验证方法、版本、时间范围和信任条件。验签核验签名与记录的绑定，Merkle 包含证明核验指定批次的成员关系，存储证明核验约定保存命题，业务验收执行指定验收规则；四类结果分别记录。标准适配接口在兼容配置中列明采用的字段、方法与验证参数，核验仅覆盖相应范围。

## 3.3.3 受控处理、外部副作用与失败语义

受控处理包括检索、摘要、脱敏、格式转换、TEE 和算力平台计算。处理任务的执行清单绑定输入对象版本、用途、密钥策略、允许的执行环境、输出位置、保留期限与资源预算。Gateway 先校验独立处理授权，再向符合环境身份与策略条件的执行器发放短期受限能力；需要 TEE 的任务同时核验环境证明与策略指定的度量值。算力平台承接按资源与执行环境调度的计算任务，结果经输出范围和来源规则校验后写回 Vault，输入输出摘要与必要运行证据进入审计记录。

支付、发信、调用生产 API、提交交易和修改第三方系统属于外部副作用。执行前自动校验 Owner 预先签署的独立操作范围、用途、目标域名或收款方、金额与频率限制，并保存 Checkpoint；执行使用稳定 `operation_id` 和幂等键，结果进入业务账本与回执。超出授权或预算的动作直接拒绝，结果未知时进入查询与对账，明确失败后按预设补偿规则处理。普通状态读取授权不包含这些能力。

失败语义至少区分：

| 失败类型               | 是否可重试                   | 处理原则                                      |
| ------------------ | ----------------------- | ----------------------------------------- |
| 身份失败 / 委托无效 / 策略拒绝 | 仅在取得有效认证或独立委托后形成新请求     | 不触及原文，保存最小拒绝回执；日志故障独立返回 pending 或 failed  |
| 对象不存在 / 版本冲突       | 按类型化冲突策略处理              | 不泄露未授权存在性；去重追加、字段合并或保留隔离分支                |
| 存储后端不可用            | 查询业务账本后，按幂等约束退避重试或降级    | 仅在持久化条件满足时报告成功；结果未知先查询                    |
| 本地回执保存失败 / 恢复中     | 按 operation\_id 查询和恢复记录 | 保持实际业务结果；回执独立返回 failed 或 pending，不重复已成功业务 |
| 证明延迟               | 可异步等待                   | 业务成功与证明完成状态分开                             |
| 外部动作失败             | 依操作语义                   | 使用幂等键、对账与补偿                               |
| 结果未知               | 停止业务重放，仅执行有界查询          | 根据操作账本、外部查询与回执自动对账；无法确定时隔离该操作并保留 unknown  |

运行机制维持三个不变量：

* 未授权的受管请求不得触及状态原文。
* 写入失败不得在回执中声明业务成功。
* 外部动作结果未知时不得无条件自动重试。
