## 3 架构与状态模型

本章把产品语言转化为技术边界：三平面说明系统如何组织，六层说明职责如何拆分，请求路径说明组件如何交互；状态模型与信任边界定义什么能被保存、迁移和证明。

架构目标是让判断、保存与证明分工明确，减少单一组件的权限集中。职责划分本身不构成密码学隔离或部署隔离保证，实际边界取决于持钥者、解密位置、运维权限和证据签发方式。

{% hint style="info" %}
**方案范围：三平面职责、六层协作、状态对象模型与信任边界。** 网络、对象、授权和受控处理通过版本化接口协作；部署配置明确密钥保管主体、解密位置、服务权限、后端持久化条件与证据验证规则。
{% endhint %}
