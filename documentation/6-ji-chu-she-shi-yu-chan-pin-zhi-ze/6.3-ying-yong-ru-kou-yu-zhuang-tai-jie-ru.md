# 6.3 应用入口与状态接入

## 6.3.1 Data Wallet 与身份控制入口

Data Wallet 是用户身份、密钥、数据资产与 Agent 状态的控制入口，通过 Reader 等访问角色和有限委托表达权限。控制台将用户操作转为签名策略或授权请求，提供以下功能：

* 查看 Vault 中的记忆、任务、成果与来源；
* 查看逻辑 Agent、Agent DID、执行实例 `instance_id` 与任务运行 `run_id`；
* 签发、查看和撤销委托；
* 管理 Vault 内容加密密钥、轮换和托管模式，并单独说明 Agent 身份签名密钥的更换流程；
* 查询访问、运行与证明记录；
* 导出 Memory Pack，发起删除和派生项处理；
* 分别控制记忆使用、训练、发布与再共享。

Agent 身份方案以“Agent 身份签名密钥 + 执行实例”确定 Agent DID。逻辑 Agent 表示跨模型持续存在的服务或角色，`instance_id` 标识执行实例，`run_id` 标识一次任务运行。模型、框架、名称或版本变化本身不创建 DID；身份签名密钥更换时创建新实例与新 DID。Data Wallet 保存经旧、新身份双签且通过 Owner 策略校验的连续性记录；旧身份不可用时使用预设恢复授权签发独立恢复声明。历史记录与声誉仍绑定其原始 DID，并通过关联查询展示。同一实例使用原密钥的受控恢复保持 DID；新的并发实例使用独立身份密钥与 DID。用户绑定、访问委托和 Agent 注册分别管理，新 DID 通过 Owner 新签委托获得权限。Vault 内容加密密钥轮换不改变 Agent DID。

Data Wallet 作为控制入口与链、Vault、Gateway 和存储后端交互，不必保存所有个人数据原文。控制台显示的状态必须来自实际策略与审计服务，不能以 UI 状态代替后端授权。撤销在相关策略执行点确认生效后阻止后续受控请求；控制台展示各执行点的生效回执、传播时间和异常状态；已取得的明文、旧密文及对应密钥不会自动收回。

## 6.3.2 Data Market 与选择性状态资产化

Data Market 通过 MEFS 保存加密内容，通过以太坊合约登记资产引用、许可与结算事件，并使用 DID 关联交易主体。内容存储与链上登记承担不同职责，DID 关联不自动证明现实身份或全部权利归属。选择性交付按资产描述清单组织原始资料、查询服务、成果、Memory Pack、经验包、Skill 和训练数据集；清单绑定确定版本、来源、权利声明、密文引用、许可范围与交付策略。

资产化由 Owner 预签的资产策略选择对象和接收范围。策略分别配置团队共享、合作方许可和开放市场三种分发范围，并限定读取、训练、再分发、有效期、价格与争议规则。交付使用资格预检、报价、支付验证和结算、授权复查、密钥封装及接收回执的顺序；已支付但明确未交付时按补偿策略处理。合约调用使用独立 `execute_external` 授权，导出和共享分别检查 `export` 与 `share` 范围。

普通个人记忆默认不进入市场；支付成功与获准访问是两项独立条件；已经下载的明文不能通过撤销远程追回。ERC-7829 只用于需要链上表示的状态资产，不是所有状态对象的默认容器。

## 6.3.3 DataDrive、Smart Layer 与 Storage API

DataDrive / Drive3 / EthDrive / LensDrive 是基于 MEFS 的文件应用入口，其中 LensDrive 面向 Lens 社交生态。Vault 导入适配器读取这些入口中的文件、社交内容和知识库，自动校验来源权限、内容完整性和接口版本，再将对象映射为带来源和策略引用的 State Object。导入配置限定命名空间、字段映射、同步方向和删除传播规则；格式不兼容或来源权限不足的对象进入隔离队列。

Smart Layer / Storage Middleware 提供 DID 登录、上传、下载、删除、文件列表、空间与流量、fileDNS 权限和购买接口。Gateway 与 Vault 通过适配层将这些文件服务映射到身份委托、对象版本、策略执行与计量，具体关系如下：

| 基础接口             | 状态服务职责        | 映射字段与控制                                                                  |
| ---------------- | ------------- | ------------------------------------------------------------------------ |
| DID 登录、签名        | Gateway 身份与认证 | Agent DID、`instance_id`、`run_id`、独立的绑定与委托、防重放                            |
| 上传 / 下载文件        | Vault 对象读写    | `namespace`、`schema_version`、`version`、`parent_refs`、`provenance`        |
| fileDNS / Reader | Gateway 策略    | 用途、期限、撤销、训练与再共享分离                                                        |
| 文件 hash          | Proof 对象承诺    | `commitment.algorithm`、`commitment.scope`、`commitment.value`、回执、审计根与证明状态 |
| 空间与流量            | 服务配额          | Vault 对象与 MEFS 后端的可解释计量                                                  |

Storage API 使用独立版本管理文件接口和状态接口。客户端从已验签的服务与价格注册表解析端口、`base_url`、令牌受众、并发限制、重放窗口、过期与刷新规则、计价单位和价格版本，并在连接时校验服务身份、版本与网络域。`request_id` 标识请求尝试，`operation_id` 标识可重试的同一业务操作，`receipt_id` 标识回执，不与 `run_id` 混用。接口迁移使用明确的兼容窗口、转换规则和路由配置；自动契约测试与对象校验通过后切换入口，历史对象及其接口语义保持可追溯。
