# 7.3 兼容性配置与版本管理

## 7.3.1 协议与客户端兼容矩阵

适配器以兼容性配置作为可执行契约，固定规范标识、传输、认证、能力映射和验证用例。客户端先读取服务能力清单，再按自身版本选择匹配配置；版本、签名、传输或能力不匹配时返回明确错误，不自动降级认证或改变业务语义。

| 组件              | 规范配置                                 | 传输或环境                          | 适配职责                                                   | 自动兼容验证                                 |
| --------------- | ------------------------------------ | ------------------------------ | ------------------------------------------------------ | -------------------------------------- |
| MEMO Gateway    | MCP 2026-07-28 配置；扩展单独列入能力清单         | 本地 stdio；远端 HTTPS 按配置承载 MCP 请求 | resources、tools、错误映射、Agent DID 与委托校验、状态读写及回执           | 请求格式、工具 Schema、无状态请求、授权拒绝、幂等写入、取消与错误传播 |
| MEFS MCP Server | MCP 存储工具配置，固定工具与后端接口版本               | 本地进程或受认证的远端服务                  | put、get、proof query 映射到 Vault 后端调用与受限存储凭据              | 内容完整性、对象版本绑定、后端故障、密钥边界与 Proof 类型验证     |
| A2A Adapter     | A2A v1.0.0 配置                        | HTTPS；流式更新按任务配置启用              | Agent Card、Task、Message、Artifact、cancel 与 Handoff 引用映射 | 身份与接收委托、流中断恢复、取消、重复任务、部分交付与结果持久化       |
| Agent Skill     | Agent Skills 格式；包哈希、包版本和 Host 配置共同标识 | 具有受控工具执行环境的 Host               | 保存、恢复、校验工作流；声明工具与资源依赖                                  | 包签名、字段模式、工具权限、文件与网络边界、执行结果回执           |
| x402 Adapter    | x402 V2 配置，绑定支付方案、网络和资产              | HTTP 402 支付流程经受认证的 HTTPS 入口传输  | 支付头、报价、授权载荷、验证、先结算后交付与补偿映射                             | 报价过期、重复授权、验证失败、结算未知、撤销复查、交付失败和退款对账     |

兼容性流水线记录测试套件版本、客户端与适配器版本、环境配置、输入数据摘要、时间和逐项结果，并生成签名报告。服务注册表引用对应报告与能力清单；发布路由只加载满足当前准入规则的配置。官方与社区客户端采用同一接口契约，维护主体、服务范围和问题跟踪入口作为独立配置记录。

## 7.3.2 标准映射与适配边界

每项外部规范对应明确的适配职责。规范名称、版本和参考地址用于绑定接口行为，外部协议对象沿用其原生字段；MEMO 对象、策略和回执保持各自版本及 snake\_case 字段约定。

| 对象           | 规范引用                                                                      | MEMO 适配方案                                            | 控制与验证边界                                  |
| ------------ | ------------------------------------------------------------------------- | ---------------------------------------------------- | ---------------------------------------- |
| ERC-8004     | [ERC-8004](https://eips.ethereum.org/EIPS/eip-8004)                       | 将 Agent DID 的外部注册、服务端点、声誉与验证记录关联到身份发现视图              | 注册和声誉不授予状态权限；请求由 Gateway 校验独立委托          |
| ERC-7857     | [ERC-7857](https://eips.ethereum.org/EIPS/eip-7857)                       | 按 Owner 资产策略封装私有 Agent 元数据，并映射转移、克隆和使用许可             | 状态范围、密钥接收者、授权用途和证据分别校验，普通记忆保持默认非资产化      |
| ERC-7829     | [ERC-7829](https://eips.ethereum.org/EIPS/eip-7829)                       | 将数据对象、Memory Pack 或 Artifact 的内容引用、存储元数据和读取策略映射到资产描述 | 链上引用不公开原文；读取受委托、密钥与内容生命周期共同约束            |
| MCP          | [2026-07-28 规范](https://modelcontextprotocol.io/specification/2026-07-28) | 将工具和资源请求映射到 Gateway 与 Vault，扩展按能力清单启用                | 每次请求校验身份、委托、版本和幂等关联；Host 执行控制与后端持久化分别落实  |
| A2A          | [v1.0.0 规范](https://a2a-protocol.org/v1.0.0/specification/)               | 将任务、消息与 Artifact 映射到任务信封、Handoff 和状态版本               | 任务完成、对象保存、本地回执与 Proof 状态分别记录             |
| Agent Skills | [格式规范](https://agentskills.io/specification)                              | 通过技能包组织操作说明、脚本、参考资料和资产                               | 包声明只表达依赖；Host 和 Gateway 分别执行代码、网络和状态权限控制 |
| x402         | [HTTP 402 说明](https://docs.x402.org/core-concepts/http-402)               | 使用 V2 支付头，经 Facilitator 验证与结算后，由 Gateway 复查授权并交付     | 支付状态独立于业务、回执和证明状态；未知结算先查单，明确交付失败按策略补偿    |

规范配置记录来源 URI、内容摘要、协议版本、接口及事件映射。配置更新先运行模式校验、契约测试、权限边界测试与历史对象回放，随后发布新的签名配置；客户端按明确版本选择路由，不依据规范名称推断额外能力。

## 7.3.3 版本、弃用与迁移说明

每个对外接口使用显式版本，并分别管理协议版本、Schema 版本、SDK 版本、服务发布版本和网络 / 合约版本。它们可以按不同节奏演进，但必须能够在一次回执中被关联。

接口弃用与迁移使用五步流程：

{% stepper %}
{% step %}
## 定义迁移

记录替代接口、影响范围、转换规则和自动验证用例。
{% endstep %}

{% step %}
## 预告

公布停止新增功能日期、兼容窗口和迁移指南。
{% endstep %}

{% step %}
## 并行

新旧版本同时运行，提供转换器和遥测。
{% endstep %}

{% step %}
## 限制

停止新接入，但不突然破坏已有任务。
{% endstep %}

{% step %}
## 下线

关闭入口，保留只读历史、校验工具和重定向。
{% endstep %}
{% endstepper %}

破坏性变更必须至少覆盖身份表示、签名域、权限语义、对象 Schema、加密格式、传输、错误码、支付方案和 Proof 验证。迁移前后应生成状态清单与校验结果，保留 `object_id`、直接父版本关系、来源及策略引用。密文原样迁移时可比较同一摘要范围下的 commitment；重新加密或格式转换时摘要可能改变，须记录旧新封装映射与转换回执，不能以“摘要必然相同”作为所有迁移方式的验收条件。

Agent 身份签名密钥更换时创建新实例和新 Agent DID，旧、新实例对连续性记录分别签名，并由 Owner 委托策略自动校验；旧密钥不可用时使用预设恢复授权的独立恢复声明。原有声誉和历史凭证保持原始 DID 归属，通过关联查询呈现；新 DID 使用 Owner 新签的委托，绑定和权限不自动复制。原密钥与同一 `instance_id` 的受控恢复保持 DID，创建新的并发实例则使用独立密钥与 DID。内容加密密钥轮换只改变数据加密和密钥封装关系，不创建新 Agent DID。

当外部协议弃用旧传输或字段时，MEMO 应把影响写入兼容矩阵，并给出最后支持版本和日期。客户端通过配置化兼容代理迁移时，代理固定截止时间、接口范围与转换规则，执行相同或更严格的认证和授权；降低控制等级的配置在加载阶段被拒绝。
