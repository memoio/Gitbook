# 8.1 开发参考

## 8.1.1 API / SDK / Schema

接口按职责分为五组，各接入协议映射到同一命令与事件模型：

| API 组    | 核心操作                               | 必要控制                           | 主要返回                         |
| -------- | ---------------------------------- | ------------------------------ | ---------------------------- |
| Identity | 注册 / 解析 Agent DID、Owner 绑定、身份连续性登记 | 主体控制证明、nonce、防重放、旧新身份签名或独立恢复声明 | DID Document、绑定记录、执行实例和连续性引用 |
| State    | 创建、读取、更新、列举、导出 State Object        | 委托、命名空间、版本前置条件、幂等键、用途策略        | 对象、版本、commitment、receipt     |
| Handoff  | 生成 / 导入 Memory Pack、记录接收结果         | 接收者密钥、用途和期限、清单完整性、依赖与冲突策略      | manifest、交接 ID、发送与接收回执       |
| Proof    | 查询回执、Trace 摘要、存储证明和 Attestation    | 证据范围、隐私裁剪、签发者与验证策略             | 证据引用、验证结果、失败原因               |
| Admin    | 配置策略、撤销委托、轮换内容加密密钥、管理配额与审计导出       | 强认证、职责分离、签名管理策略、范围及预算约束        | 变更记录、数据密钥版本、审计事件、恢复点         |

Agent DID 绑定身份签名公钥与执行实例。身份签名密钥更换时创建新 `instance_id` 和新 DID；模型、框架、名称、版本元数据变化以及内容加密密钥轮换均不改变 DID。`instance_id` 标识执行实例，`run_id` 标识一次任务运行。正常接续由旧、新实例对连续性记录签名，并校验 Owner 的委托策略；旧身份不可用时，预设恢复授权签署独立恢复声明。历史凭证继续绑定旧 DID，新 DID 通过 Owner 签署的新委托取得权限。

State Object 使用以下结构。MEMO 自有字段采用 snake\_case；外部规范的原生字段、HTTP 头和 ABI 名称保留原写法，由适配层完成显式映射。

```json
{
  "schema_version": "memo.state_object/1",
  "object_id": "mem_project_a_001",
  "type": "memory",
  "owner": "did:memo:user:example",
  "namespace": "project/a",
  "version": "v_001",
  "parent_refs": [],
  "provenance": {
    "source_type": "user_input",
    "source_refs": ["source://project/a/brief"],
    "producer_agent_did": "did:memo:agent:example",
    "producer_instance_id": "instance_example",
    "producer_run_id": "run_20261016_001",
    "confirmation_status": "confirmed",
    "confirmation_method": "policy_validation",
    "confirmed_by": "did:memo:service:policy-engine",
    "confirmation_policy_ref": "policy_project_a_memory_admission_v1"
  },
  "policy_ref": "policy_project_a_v1",
  "content_ref": "encrypted://content/mem_project_a_001/v_001",
  "commitment": { "algorithm": "sha256", "scope": "ciphertext", "value": "<digest>" },
  "created_at": "2026-10-16T02:00:00Z",
  "expires_at": null,
  "proof_refs": []
}
```

`object_id` 是稳定逻辑标识；`version` 是服务端分配的不透明、不可变、唯一字符串。客户端使用返回值和父版本引用比较版本关系，不对 `v_001` 等字符串递增或按字面排序。`schema_version` 标识结构版本，`parent_refs` 只记录直接父版本的 `object_id` / `version`。原始来源、跨对象依赖及变换关系记录在 `provenance` 中。`type` 通过 Schema 注册表约束为 `memory`、`checkpoint`、`trace`、`artifact` 等对象类型。

Memory 准入引擎自动校验来源、签名、用途、字段模式与冲突策略。`confirmation_status=confirmed` 表示对象通过 `confirmation_policy_ref` 指定的准入策略；`confirmation_method=policy_validation` 与 `confirmed_by` 标识处理方式及执行主体。该状态不替代来源真实性与业务事实核验，策略拒绝或隔离的候选保留原因和来源引用。

`commitment.algorithm`、`scope`、`value` 共同定义摘要。`scope=ciphertext` 绑定实际存储的完整加密封装字节；封装采用 Schema 注册表指定的序列化与算法配置，摘要计算覆盖封装声明的字节范围。`content_ref` 是稳定内容引用，通过独立定位映射连接物理后端；原样复制密文只更新位置映射，并保留原版本与摘要。重新加密或格式转换创建新对象版本，记录新封装摘要、旧新映射与转换回执。验证器按对象的算法与封装配置执行核验，未知配置直接拒绝。

`proof_refs` 固定为对象创建时已知的证据快照。异步新增证据追加至按 `(object_id, version)` 索引的 Proof Registry，记录证据类型、签发者、时间、状态和验证引用。查询响应分别返回原对象封装与补充证据，聚合层合并展示对象快照与 Registry 记录；对象内的 `proof_refs` 及既有不可变版本保持原样。

写入命令提交业务载荷、命名空间、策略引用与版本前置条件；新建时服务端分配或校验唯一 `object_id`，更新时保持既有 `object_id`，并生成新 `version`、时间、策略准入结果和回执关联。客户端来源声明经验证后写入，准入状态由策略引擎生成。明文 `content` 表达客户端加密前的载荷，持久化路径保存加密封装与 `content_ref`。Gateway 仅在受控计算配置明确授予解密能力时处理明文。授权操作统一为 `read`、`write`、`search`、`export`、`import`、`delete`、`train`、`share`、`execute_external`；`create_checkpoint` 工具映射到 `write`，并使用 Checkpoint 的独立资源与用途策略。

写接口以 `Idempotency-Key` 绑定一次业务动作，更新接口检查前置版本或 ETag。委托登记按 `issuer` 与 `nonce` 去重；同一委托在有效期和授权范围内可多次使用，逐请求防重放与业务幂等分别校验。冲突处理采用确定性规则：独立字段合并、追加记录按稳定键去重、其余冲突保留分支并隔离或拒绝提交，避免无声覆盖。列表使用不透明游标；时间使用带时区格式；大对象采用分块上传和受限上传凭据。错误响应包含稳定错误码、错误阶段、可重试性和关联标识，并避免向未获权限的调用者泄漏资源是否存在。

请求通过 `Memo-Request-Proof` 携带[4.1.2](/broken/pages/8a5b481a582195e2bc031837f88b8d24f9555b38#c4-1-2)定义的签名封装，固定主体、实例、受众、网络域、方法、目标、业务载荷摘要、`operation_id`、时间窗和独立 `request_nonce`。身份 challenge、委托登记 nonce、单请求 nonce、合约调用 nonce 与外部支付授权 nonce 分别校验。重试更新逐请求字段，保留业务操作标识；幂等指纹排除请求标识、时间、签名与令牌。业务账本按 Owner、命名空间和业务操作域原子占位，同键异指纹拒绝；相同操作的状态查询和结果返回继续检查当前授权及撤销状态。

`request_id` 标识单次请求，`operation_id` 标识跨重试的同一业务动作并与 `Idempotency-Key` 关联，`receipt_id` 标识回执，`run_id` 标识任务运行。返回状态分别记录如下：

| 字段                | 取值                                                                                                          | 含义与处理规则                                 |
| ----------------- | ----------------------------------------------------------------------------------------------------------- | --------------------------------------- |
| `decision`        | `allow` / `deny`                                                                                            | 策略决定，独立于业务执行结果                          |
| `business_status` | `not_executed` / `succeeded` / `failed` / `unknown`                                                         | 业务状态；`unknown` 先查询同一 `operation_id` 并对账 |
| `receipt_status`  | `available` / `pending` / `failed`                                                                          | 本地回执材料的获取与处理状态，失败进入恢复队列                 |
| `proof_status`    | `not_requested` / `pending` / `available` / `failed`                                                        | 后台证明处理状态；`available` 只表示材料可获取，验证结果独立记录  |
| `payment_status`  | `not_required` / `required` / `verified` / `settled` / `failed` / `unknown` / `refund_pending` / `refunded` | MEMO 内部支付状态映射，独立于外部协议字段和业务结果            |

业务写入、本地回执持久化、异步批量锚定分别提交状态。`business_status=succeeded` 且 `proof_status=pending` 时查询证明任务，不重复写入。回执恢复按 `operation_id` 核对业务提交日志与已有 `receipt_id`，防止补记触发重复副作用。支付结果为 `unknown` 时先查单和对账；退款任务使用原支付引用与独立幂等键。

SDK 负责签名、序列化、重试、分页、版本协商和错误类型，授权判断由 Gateway 与策略执行点负责。Schema 注册表记录类型、版本、序列化配置和兼容规则：新增可选字段保持向后兼容；删除字段、改变含义或收紧枚举形成主版本变化；扩展字段放入注册扩展区并原样保留；未知安全字段和必需能力拒绝处理。

## 8.1.2 合约方法与事件

链上合约保存公共验证、结算或治理所需的最小状态。Contract Descriptor 将合约域绑定到链 ID、地址、代码哈希、部署交易、ABI、源代码引用和升级策略；加载器校验描述文件签名、链标识、代码与 ABI 一致性后建立调用映射。

| 合约域              | 方法职责                         | 事件职责              | Agent State Layer 映射          |
| ---------------- | ---------------------------- | ----------------- | ----------------------------- |
| 身份 / 注册          | 注册身份、更新元数据、记录撤销和身份连续性承诺      | 注册、元数据变化、撤销、连续性登记 | Agent DID 解析及撤销锚点；新旧 DID 独立保留 |
| 委托 / Attestation | 签发、验证、撤销及登记声明承诺              | 声明签发、声明撤销         | Owner 绑定、访问委托、TEE 或服务声明       |
| 存储 / 挑战          | 提交 commitment、发起挑战、提交证明、登记修复 | 订单创建、挑战、证明受理、修复结果 | MEFS / Meeda 存储责任和可用性核验       |
| 结算 / 质押          | 存入、提取、结算、罚没                  | 资金存入、结算、奖励、罚没     | 存储、验证、计算与服务费用                 |
| 数据资产             | 创建资产、授予用途许可、转移、撤销授权          | 资产登记、权限变化、转移记录    | Owner 策略选定的数据或 Agent 元数据资产    |

方法描述包含调用权限、参数、返回值、事件、状态变化、费用、失败条件、防重放、重入控制、暂停行为与升级策略。事件描述包含索引字段、唯一标识、最终性、链重组处理和链下对象引用。签名域绑定网络、合约、方法、参数摘要、有效期和 nonce，避免跨链、跨合约及跨用途重放。

链上观察作为签名业务回执的独立证据项，使用下列结构关联业务操作与链事件。尖括号参数由操作上下文、Deployment Registry 和链索引器解析，校验通过后写入记录。

```json
{
  "schema_version": "memo.chain_observation/1",
  "operation_id": "<idempotent-operation-id>",
  "request_id": "<request-attempt-id>",
  "receipt_id": "<receipt-id>",
  "network": "<network-id>",
  "chain_id": "<chain-id>",
  "contract": "<verified-address>",
  "transaction_hash": "<hash>",
  "block_ref": "<block-number-or-hash>",
  "finality_status": "<observed-finality>",
  "event_ref": "<contract-event-reference>",
  "state_ref": { "object_id": "mem_project_a_001", "version": "v_001" },
  "observed_at": "2026-10-16T02:00:00Z"
}
```

链索引器根据链配置更新观察状态；链重组触发重新核验并撤下受影响观察的最终性标记。索引器追加重核记录和关联回执验证结果，不改写已签名声明，也不重做链下业务。重放执行前先核对 `operation_id` 及实际副作用。签名、事件真实性、日志覆盖、存储命题和业务成果分别核验。

可升级合约的描述文件记录代理、实现、管理员角色、时间锁与升级事件。权限变化和升级通过签名策略校验、模拟执行、时间锁及执行后代码哈希检查生效，部署注册表和历史记录同步保存前后映射。

## 8.1.3 网络、合约地址与环境

Deployment Registry 是网络、合约和服务端点的配置入口。构建与部署流程将组件清单、网络配置和部署交易输出装配为注册表，使用发行密钥签名。调用方从受信任的注册表引用加载配置，固定环境和版本，并执行自动验证。

```yaml
schema_version: memo.deployment_registry/1
release: <memo-release>
environment: <local-or-devnet-or-testnet-or-mainnet>
network:
  name: <network-name>
  chain_id: <chain-id>
  rpc:
    - <official-rpc-url>
contracts:
  - name: <contract-name>
    proxy: <optional-address>
    implementation: <verified-address>
    deployment_tx: <transaction-hash>
    abi: <versioned-artifact-reference>
    source_verification: <explorer-or-repository-reference>
services:
  gateway: <base-url>
  proof: <base-url>
  facilitator: <base-url>
published_at: <timestamp>
signature: <release-signature>
```

尖括号项是配置参数：`release` 与 ABI 引用来自版本化构建清单；网络和 RPC 来自所选网络描述；地址、部署交易和代码验证引用来自部署输出；服务 URL 来自受信任的服务发现记录；时间与签名由发布作业产生。仅使用本地状态的配置可省略链模块与 Facilitator；启用的模块必须具备完整依赖。加载器拒绝未解析参数、过期签名、环境冲突及不在端点白名单中的 URL。

| 环境                   | 目的             | 数据与资金        | 运行控制                                |
| -------------------- | -------------- | ------------ | ----------------------------------- |
| Local（开发环境）          | 离线开发、单元验证、故障模拟 | 测试数据和本地测试密钥  | 可重建隔离环境；与日常使用的 Local Vault 部署形态分开配置 |
| Devnet               | 团队集成、协议及迁移验证   | 无价值测试资产      | 网络重置产生版本事件，客户端刷新注册表并清理失效引用          |
| Testnet              | 互操作、负载及恢复测试    | 测试资产、合成或脱敏数据 | 固定测试版本，迁移窗口和故障场景写入测试配置              |
| Mainnet / Production | 业务结算和长期状态      | 业务数据、密钥及结算资产 | 最小权限、密钥隔离、变更控制、恢复点和服务等级策略           |

初始化依次核验发行签名、Schema、环境名、`chain_id`、地址格式、代码哈希、ABI 摘要、端点证书和服务健康；任一必要校验失败，相关模块停止接入并返回明确错误。客户端按注册表版本缓存端点，收到签名更新后重新验证，避免跨环境引用旧地址。
