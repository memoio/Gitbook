# 8.2 服务与兼容信息

## 8.2.1 产品计费、存储与流量额度

计费由计量器、版本化 PriceBook、报价器、预算策略和结算适配器组成。订阅、按量、预留容量和链上按次支付映射到统一账本。PriceBook 定义单位价格、额度、地区或网络、有效期、舍入规则、失败费用和服务等级，报价器在执行前锁定所用价格版本与费用上限。

| 计量项                 | 单位                | 价格与服务规则                   |
| ------------------- | ----------------- | ------------------------- |
| 存储容量                | GiB-month / 对象月   | 副本与纠删码开销、最短保留期、删除与计费截止条件  |
| 读取 / 下载             | GiB、请求数           | 缓存、出口流量、跨区域费用             |
| 写入 / 版本             | 请求、对象或 GiB        | 小对象最小计费单位、失败写入、历史版本保留     |
| Proof / Attestation | 次或批次              | 证明类型、链上 Gas、失败处理成本        |
| Gateway             | 请求、活跃 Agent 或策略评估 | 包含额度、峰值限流、审计导出            |
| 受控计算                | CPU/GPU/TEE 时间、任务 | 冷启动、超时、模型和镜像成本            |
| 结算                  | 交易或成交额            | Facilitator 费、网络费、退款与冲正费用 |

Quote 绑定 `quote_id`、`pricebook_ref`、资产、税费规则、有效期、最大数量、费用上限、结算网络、补偿规则和 `operation_id`。计量事件携带单位、数量、时间窗口、去重键及服务证据引用，账单使用确定性舍入与去重规则汇总，同一操作的网络重试不重复收费。

长任务先预留预算，再按执行 Checkpoint 结转实际消耗；阈值内的扩容必须属于 Owner 预签署的预算策略。额度耗尽时停止新增不可撤销费用、保存恢复点并返回预算错误，不通过重试绕过额度。任务完成或取消后释放剩余预留。

失败收费按阶段处理：资格预检拒绝不进入业务结算；已支付而交付失败的操作创建退款或冲正任务；已交付服务按记录计量；证明或节点责任失败按报价所引用的补偿策略处理。不可退回的网络成本在报价中单独列项。账单只关联操作、计量和必要证据，不保存任务原文。

x402 采用第 7 章的固定流程：资格预检 → 402 报价 → 客户端携带支付授权重试 Gateway → Facilitator 验证 → 结算 → Gateway 再鉴权 → 执行或交付。Facilitator 不访问状态明文，也不替代资源授权。结算结果为 `unknown` 时查单与对账；已支付而交付失败的操作按补偿策略进入 `refund_pending`。仅在收到与原 `operation_id`、退款金额和收款方匹配的可核验退款结果后，支付状态才转为 `refunded`；退款失败或结果未知时保留 `refund_pending`，记录原因并先查单、对账，避免重复退款。业务、支付、回执和证明状态独立记录。

PriceBook 与服务等级配置通过签名注册表分发，生效时间、地区、网络与版本写入每份报价。已接受报价按其锁定的版本结算，价格更新只作用于生效范围内的新报价。金额和额度参数由配置注入，加载时校验非负值、精度、币种或资产标识、有效期与预算上限。

## 8.2.2 客户端、框架与后端适配

适配器通过 Compatibility Profile 声明协议版本、接口能力、对象 Schema、认证方式、状态映射、维护责任和验证入口。客户端先匹配必要能力，再选择适配路径；版本或权限不匹配时返回确定的兼容性错误。

| 分类                  | 接入对象                          | 适配职责                                    | 描述文件内容                 |
| ------------------- | ----------------------------- | --------------------------------------- | ---------------------- |
| Agent Host / Client | MCP、A2A 或直接 API 客户端           | 协议消息映射到 Gateway 命令                      | 客户端与协议版本、传输、认证、工具和资源能力 |
| Agent Framework     | 编排、工具调用和多 Agent 框架            | memory、checkpoint、artifact、tool wrapper | 状态映射、恢复条件、依赖、版本及验证用例   |
| Memory Engine       | 向量库、知识图谱、摘要与记忆组件              | 来源导入、候选准入、索引与对象映射                       | 原始对象引用、索引版本、准入策略和删除传播  |
| Storage Backend     | Local、Hosted、MEFS             | Vault backend interface                 | 封装、冗余、证明、保留与迁移规则       |
| Identity / Wallet   | Data Wallet、DID wallet、企业 IdP | 签名、OIDC / VC 映射、委托                      | 信任域、发行者、密钥控制、恢复和撤销规则   |
| Settlement          | 账户余额、链上结算、x402、企业账单           | 统一报价与支付状态映射                             | 资产、网络、费用、最终性、退款及幂等规则   |

Compatibility Profile 将维护者与服务责任独立登记；社区适配器同样执行签名、依赖锁定和接口验证。运行时以 `compatible`、`incompatible` 记录配置匹配结果，以健康状态记录服务可达性，以验证报告记录具体测试范围，三者分别判断。必要能力只根据显式声明和验证规则匹配，不由产品名称推断。

Local 由用户或组织管理设备及密钥，Hosted 由托管服务管理资源与运行维护、按策略连接用户密钥或组织 KMS，MEFS 通过分布式存储订单管理保存责任。三种形态共享 `object_id`、父版本图、`policy_ref`、`provenance` 和证据引用。迁移使用清单和转换回执保留逻辑连续性；原样密文迁移只更新 `content_ref` 对应的位置映射，保留原版本与摘要；重新加密或格式转换创建新版本，记录新封装与摘要映射。

## 8.2.3 术语表与运行状态索引

下表统一产品、身份、对象与证据术语：

| 术语                       | 统一含义                                   | 关键边界                     |
| ------------------------ | -------------------------------------- | ------------------------ |
| Agent State Layer        | MEMO 面向 Agent 的可信状态基础设施                | 总体架构包含存储、控制与证据职责         |
| MEMO Protocol            | 协议、网络角色和经济结算底座                         | 上层产品通过协议契约使用底层能力         |
| MEFS                     | 去中心化存储网络                               | 负责存储订单、保存、冗余、修复与证明       |
| MEMO Vault               | 状态对象、版本、加密和多后端存储层                      | 后端位置与对象语义分别管理            |
| MEMO Agent Gateway       | 身份、委托、策略与协议接入入口                        | 管理受管请求，不能追回已披露明文         |
| MEMO Proof               | 来源、访问、运行、存储等证据的组织和核验层                  | 每类证据绑定明确命题和时间范围          |
| 用户身份                     | 数据所有者或控制者身份                            | 通过独立委托授权执行主体             |
| Agent DID                | 绑定身份签名公钥与执行实例的执行主体标识                   | 更换身份签名密钥创建新实例和新 DID      |
| `instance_id` / `run_id` | 分别标识执行实例与一次任务运行                        | 多次任务运行可属于同一执行实例          |
| 身份签名密钥 / 内容加密密钥          | 分别用于主体签名与内容保护                          | 内容加密密钥轮换不改变 Agent DID    |
| Memory                   | 可供后续任务复用的记忆单元                          | 候选通过准入策略后进入长期记忆，事实核验独立进行 |
| State Object             | 版本化、可授权和可核验的通用状态对象                     | 版本不可变，父引用只记录直接父版本        |
| Trace                    | 一次运行的步骤、调用和结果关系记录                      | 保存可观察事件与摘要，控制隐私范围        |
| Artifact                 | 可交付的文档、代码、报告或数据等成果                     | 交付与符合性验收分别记录             |
| Memory Pack              | 清单化的加密状态导出与交接包                         | 绑定接收者、用途、范围和期限           |
| Receipt                  | 签发者对访问、变更、支付或交付事件的签名声明                 | 验签不等于事件真实性、日志完整或业务成功     |
| Commitment               | 由 `algorithm`、`scope`、`value` 定义的承诺或摘要 | 比较时保持算法、范围与封装一致          |
| Attestation              | 发行者对特定声明的可验证签署                         | 受发行者信任、撤销与验证策略约束         |

运行状态按职责分别记录：

| 状态域    | 记录内容                                              | 自动处理机制            |
| ------ | ------------------------------------------------- | ----------------- |
| 部署配置   | Local、Hosted、MEFS 及启用的服务模块                        | 根据注册表装配依赖并检查密钥与端点 |
| 接口匹配   | 协议、Schema、适配器和必要能力                                | 匹配成功建立会话，失败返回兼容错误 |
| 身份与授权  | 注册、绑定、委托、有效期、撤销                                   | 请求时验签、校验用途与撤销状态   |
| 候选准入   | 来源、规则结果、拒绝或隔离原因                                   | 策略通过后写入，冲突保留分支    |
| 业务与凭证  | `business_status`、`receipt_status`、`proof_status` | 分开持久化、查询、恢复与验证    |
| 支付     | `payment_status` 及原交易引用                           | 幂等结算、查单、对账和补偿     |
| 对象生命周期 | 活动状态、期限、删除与保留规则                                   | 按后端传播索引、密钥与副本处理任务 |
