# 9.2 支持与维护

## 9.2.1 FAQ

<details>

<summary>MEMO Agent State Layer 是新的链或新的存储网络吗？</summary>

MEMO Agent State Layer 是以 MEMO Protocol 为底座、连接 MEFS、Meeda、身份、验证和执行能力的状态基础设施。Vault 管理状态对象，Gateway 管理受管访问，Proof 组织证据；网络与合约配置通过 Deployment Registry 绑定，状态层依协议接口使用这些基础能力。

</details>

<details>

<summary>MEMO Protocol、MEFS、Data Wallet、Data Market 和 Meeda 分别承担什么职责？</summary>

Protocol 提供共同协议与网络规则，MEFS 承担去中心化存储，Data Wallet 管理用户身份和密钥控制，Data Market 负责选择性授权交付，Meeda 提供数据可用性证据。各产品保留独立的接口与协议边界，通过适配器和版本化服务清单组合。

</details>

<details>

<summary>用户身份和 Agent 身份为什么要分开？</summary>

用户是数据和授权的控制者，Agent 是接受委托的执行主体。独立委托限定范围、操作、用途和期限，执行主体可以暂停、更换或撤销，其变化不自动转移用户所有权。`instance_id` 标识执行实例，`run_id` 标识一次任务运行。

</details>

<details>

<summary>Agent DID 能证明 Agent 属于某个用户吗？</summary>

DID 表达执行主体标识，签名证明密钥控制。Owner 绑定使用用户签名的绑定声明和 Agent 控制证明，记录有效期、撤销信息与签名密钥标识。绑定关联与访问委托分开保存，Gateway 对每次请求独立检查委托和策略。

</details>

<details>

<summary>更换模型、执行实例或密钥会改变 Agent DID 吗？</summary>

Agent DID 绑定身份签名公钥与执行实例。更换身份签名密钥时创建新 `instance_id` 和新 DID；模型、框架、名称和版本元数据变化以及内容加密密钥轮换不改变 DID。旧、新 DID 通过签名连续性记录关联，旧身份不可用时由预设恢复授权签署独立恢复声明。历史凭证保留原 DID，新身份通过 Owner 签署的新委托取得权限。

</details>

<details>

<summary>Memory、State Object、Trace 和 Artifact 有什么区别？</summary>

Memory 是后续任务可复用的记忆；State Object 是通用的版本化状态容器；Trace 记录一次运行的步骤、工具和结果；Artifact 是可交付成果。它们通过对象引用关联，并分别配置生命周期和权限。

</details>

<details>

<summary>MEMO 会保存 Agent 的完整思维过程吗？</summary>

Trace 保存可观察的输入输出引用、工具调用、决策摘要、结果、错误与策略决定，并按隐私规则裁剪。内部隐含推理不属于默认采集字段；审计依据可验证事件、授权和结果记录展开。

</details>

<details>

<summary>所有数据都会上链吗？</summary>

状态原文、密钥和高频读写留在链下，链上保存必要身份承诺、审计根、证明结果、结算和治理记录。Meeda 将 blob 保存在链下并登记承诺。各对象在 Schema 和部署策略中声明公开范围及保留方式。

</details>

<details>

<summary>所有记忆都会成为 NFT 或进入 Data Market 吗？</summary>

日常状态默认私有。只有 Owner 签名策略选定且通过来源许可、用途、敏感数据与接收者资格检查的对象进入资产和交付流程，读取、训练、再分发和所有权分别授权。

</details>

<details>

<summary>已经撤销的权限能收回对方看过的明文吗？</summary>

撤销在策略执行点生效后阻止后续受控请求和密钥发放，传播通过版本与生效记录追踪。已经取得的明文、旧密文及对应密钥仍由接收环境控制。最小披露、短时授权、受控计算、密钥轮换和审计共同约束后续访问，不能远程追回已披露内容。

</details>

<details>

<summary>存储证明是否能证明记忆内容正确？</summary>

存储证明核验指定数据承诺在约定窗口内的存储命题。来源签名、引用、运行证据和业务规则分别处理来源、事件及成果符合性；某一类证明通过不会自动使其他命题成立。

</details>

<details>

<summary>MCP、A2A 和 Agent Skills 是否会替代 MEMO API？</summary>

MCP 连接工具和资源，A2A 连接 Agent 协作，Agent Skills 打包操作说明，REST / SDK 提供直接集成。适配器将各入口映射到同一状态、授权和回执语义，Compatibility Profile 匹配标准版本、适配器版本、认证方式和必要能力。

</details>

<details>

<summary>x402 支付成功后就一定可以读取状态吗？</summary>

资源交付同时要求支付条件和当前访问策略通过。流程为资格预检、402 报价、客户端携带授权重试 Gateway、Facilitator 验证与结算、Gateway 再鉴权、执行或交付。Facilitator 不读取状态明文，也不授权资源。已结算而交付失败的操作进入退款或冲正，未知结算先查单与对账。

</details>

<details>

<summary>如何在 Local、Hosted 和 MEFS 之间迁移？</summary>

导出器生成带版本、来源、权限和证据引用的 Memory Pack，接收端检查清单、依赖、接收者授权与封装。同一密文迁移更新稳定 `content_ref` 对应的位置映射，保留原版本和摘要；重新加密或格式转换创建新版本，记录旧新封装、摘要映射和转换回执。逻辑对象与父版本图持续保留，新的身份仍使用独立委托。

</details>

<details>

<summary>删除状态后是否立即从所有介质消失？</summary>

删除任务分别处理活动对象、索引、缓存、密钥与后端副本，返回各处理阶段和保留策略。分布式副本及备份按配置清理，链上承诺受链的保留规则约束。删除状态与授权撤销分开记录，避免把停止访问误解为所有介质同步清空。

</details>

<details>

<summary>客户端如何选择可接入的服务能力？</summary>

客户端加载签名服务清单，读取 `feature_set`、协议与 Schema 版本、环境和认证方式，匹配 Compatibility Profile，并执行必要端点健康检查。依赖完整、权限和配置匹配后建立会话；异常时返回缺失能力、版本冲突或端点错误，不绕过鉴权降级连接。

</details>

## 9.2.2 排障、支持与安全反馈

诊断器先识别失败层级，再按状态与幂等规则处理。诊断包采用字段白名单、密钥与凭据扫描、原文裁剪和加密传输，避免把私钥、完整 token、解密后的 Memory Pack 或用户原文送入工单与公共频道。

| 现象           | 检查项                                  | 处理动作               | 可记录的诊断信息                                    |
| ------------ | ------------------------------------ | ------------------ | ------------------------------------------- |
| 身份解析失败       | DID 格式、网络、签名密钥、注册与绑定记录、解析规则          | 停止身份降级，返回解析错误      | `request_id`、DID 摘要、解析器版本、错误码               |
| 无权限 / 403    | 委托范围、期限、动作、命名空间和撤销状态                 | 拒绝执行，不以管理员密钥绕过     | `policy_ref`、决策摘要、Agent DID、时间              |
| 版本冲突         | `expected_parent_version`、并发更新、直接父版本 | 按规则合并、去重追加或保留分支隔离  | `object_id`、`version`、操作顺序                  |
| 读取或解密失败      | 内容引用、数据密钥版本、封装接收者                    | 隔离失败读取，检查封装和授权     | commitment、后端、`key_id`、错误阶段                 |
| Proof 验证失败   | 算法与范围、时间窗、签发者、链最终性                   | 保存失败原因，与业务状态分开     | `proof_id`、验证器版本、区块引用                       |
| Proof 处理中    | `proof_status=pending`、后台任务与锚定批次     | 查询或恢复证明任务，不重做成功写入  | `operation_id`、`receipt_id`、证明任务标识          |
| 写入结果未知或回执处理中 | 状态版本、提交日志、回执持久化、幂等记录                 | 按原操作查询、对账和恢复       | `operation_id`、各次 `request_id`、`receipt_id` |
| 支付重复 / 失败    | 幂等键、资产、网络、结算和交付状态                    | 查单、对账、恢复或补偿，避免重复扣费 | `operation_id`、`payment_ref`、响应码            |
| Handoff 不完整  | manifest、缺失块、接收回执、权限期限               | 隔离导入包，按清单恢复传输      | `pack_id`、`manifest_hash`、缺失对象列表            |
| 节点不同步        | 网络、时钟、磁盘、版本、peer 状态                  | 按恢复配置同步，保留数据目录与证据  | 节点版本、健康摘要、日志时间窗                             |

标准诊断包记录软件版本、环境、网络和 `chain_id`、非敏感对象与操作标识、错误码、时间窗、重现步骤、预期与实际结果、最近配置变化和脱敏日志。`request_id`、`operation_id`、`receipt_id`、`run_id` 分别对应请求、业务动作、回执和任务运行。支付、业务、回执与 Proof 分别查询，`decision=allow` 只表示策略允许。

事件分级与响应规则如下：

* **S0 / Critical**：私钥或大规模明文泄露、未经授权的不可逆外部操作、共识或结算完整性受损；立即隔离影响范围，暂停对应执行权限并启动密钥、委托及证据处置流程。
* **S1 / High**：跨租户访问、撤销失效、系统性数据不可用或重复结算；阻断扩散，保留证据并运行授权、恢复与对账程序。
* **S2 / Medium**：单租户中断、可恢复数据或兼容问题；按服务等级配置派发恢复任务，记录进展、重试和回退结果。
* **S3 / Low**：文档、体验和低影响运行问题；按维护队列处理并关联版本记录。

私密安全反馈入口从 Official Links 注册表解析，记录加密报告方式、接收者密钥、受理范围和响应策略。接收服务自动生成报告回执和事件标识，诊断器裁剪无关用户数据，响应流程按配置协调隔离、修复、验证和披露。公开记录包含受影响范围、密钥与授权处置、版本和用户自查方法；敏感利用细节遵循披露策略。

## 9.2.3 版本记录与兼容迁移

版本记录连接用户影响、接口契约、兼容性和自动验证材料。构建系统从提交、Schema 差异、测试报告、注册表和迁移作业生成记录，校验所有引用与制品摘要后签名归档。机器可读条目绑定版本、日期、配置范围和变更类型。

```markdown
## <release_version> — <release_date>

- schema_version: <schema_set_version>
- feature_set: <接口与操作能力集合>
- compatibility: <协议、客户端、框架、后端与环境组合>
- validation_refs: <自动验证报告与制品摘要>
- registry_ref: <签名部署注册表>

### Added
- <接口、字段或能力及其作用域>

### Changed
- <行为变化、受影响对象与配置>

### Fixed
- <错误条件、修复行为与回归验证引用>

### Security
- <风险范围、控制规则、处置方式和验证引用>

### Deprecated
- <接口>：兼容截止 <date>；替代接口 <replacement>；转换器 <converter_ref>

### Removed
- <移除接口、最后兼容版本和迁移入口>

### Migration
1. <加密备份与恢复点>
2. <依赖及兼容检查>
3. <幂等迁移作业>
4. <完整性、授权与业务核验>
5. <失败回退策略>

### Operational boundaries
- <适用条件、限制及运行处理规则>
```

弃用配置同步到文档、SDK、服务响应及机器可读公告，客户端自动检测接口的兼容截止和替代映射。身份、密钥、加密、Schema 或合约迁移执行干运行、恢复点、正式转换、完整性校验和失败回退；身份签名密钥更换与内容加密密钥轮换分开处理。历史文档保留适用版本、替代入口和兼容范围，并从当前部署入口隔离。
