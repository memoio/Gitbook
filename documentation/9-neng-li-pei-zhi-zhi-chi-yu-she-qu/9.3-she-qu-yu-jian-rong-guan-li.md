# 9.3 社区与兼容管理

## 9.3.1 贡献流程与服务入口

贡献类型包括文档、代码、适配器、Schema、验证用例、研究模型和节点配置。仓库与贡献规则由签名 Official Links 注册表发现；变更管道按贡献类型执行以下步骤：

{% stepper %}
{% step %}
## 校验基础信息

校验仓库、分支、许可证、贡献协议、行为准则和提交身份。
{% endstep %}

{% step %}
## 关联问题与影响

关联 Issue 或架构记录，声明问题、边界、配置及迁移影响。
{% endstep %}

{% step %}
## 执行代码验证

对代码执行构建、单元与集成验证、依赖扫描和接口差异检查。
{% endstep %}

{% step %}
## 执行增强验证

对 Schema、签名域、加密格式、经济参数及合约执行增强验证、模拟和策略门槛检查。
{% endstep %}

{% step %}
## 生成并核对文档内容

生成术语、示例、图表、兼容性描述及变更记录，并核对内容引用。
{% endstep %}

{% step %}
## 发布与部署

在授权策略和自动验证均通过后生成签名制品，更新注册表，按部署策略滚动装配并保留回退点。
{% endstep %}
{% endstepper %}

文档使用统一术语与编号，图表和绘图提示词共享节点及关系定义，示例使用非敏感参数。中文与英文文档引用同一术语表、Schema 与服务清单；检查器自动验证内部链接、配置参数、JSON / YAML 格式和图号对应关系。

适配器清单登记维护者、许可证、依赖、协议与 Schema 版本、权限、验证范围和服务责任。发布管道以锁定依赖和测试配置构建制品，运行时仍执行授权、必要能力匹配与健康检查。维护责任、功能匹配和运行健康分别表达。

Official Links 以版本化注册表统一管理代码、服务、支持、安全与计费入口。各条目包含 URL、用途、环境、责任角色、认证方式、有效期、签名与关联配置；客户端先校验注册表，再按用途访问指定入口。

| 服务入口               | 注册键                         | 配置与发现规则                       |
| ------------------ | --------------------------- | ----------------------------- |
| Official Links 总入口 | `official_links`            | 受信任根、注册表版本、发行签名和有效期           |
| 代码、版本和贡献入口         | `repositories` / `releases` | 仓库、分支、许可证、贡献规则和制品签名           |
| 部署与示例入口            | `deployment` / `examples`   | 环境、组件清单、访问条件、样本数据和验证作业        |
| 网络浏览器与状态页          | `explorer` / `status`       | 网络标识、端点、监测范围和健康规则             |
| 技术支持与社区            | `support` / `community`     | 认证方式、受理范围、责任角色和响应策略           |
| 私密安全反馈             | `security`                  | 加密报告地址、接收者密钥、事件回执和披露规则        |
| 合作与企业服务            | `enterprise`                | 服务范围、接入条件、联系端点和身份校验           |
| 价格、额度与计费           | `pricing`                   | PriceBook 引用、单位、资产、额度、版本及生效范围 |

服务注册作业验证 URL、证书、环境与关联版本；安全和计费入口使用受限用途的签名条目。地址更新通过签名版本通知客户端，过期或校验失败的入口停止使用并返回错误，避免从非受信任来源替换端点。

## 9.3.2 产品映射与文档迁移

各产品按下表连接 Agent State Layer。接口、文档和工具通过版本与永久引用保持连续性，迁移作业将旧接口映射到目标契约并保留恢复路径。

| 产品 / 接口域                              | 相关章节              | 职责映射与迁移规则                   |
| ------------------------------------- | ----------------- | --------------------------- |
| MEMO Protocol 六层                      | 2.1、3.1、6.1       | 为状态层提供协议能力域，保持各层职责及接口边界     |
| MEFS 用户 / Provider / Keeper（Guardian） | 6.1、8.3           | 承担状态密文保存、挑战、修复和服务结算         |
| Data Wallet / MEMO DID                | 1.2.6、5.1、6.3.1   | 连接用户控制、Agent DID、独立绑定与委托链   |
| Data Market                           | 1.2.7、6.3.2、7.2.3 | 将数据、状态、知识和成果映射为选择性交付对象      |
| Meeda / DA / Lightnode                | 1.2.8、6.2         | 向 Proof 提供保留协议假设的可用性证据      |
| DataDrive                             | 6.3.3             | 文件接口映射到 Artifact 和通用文件操作    |
| Smart Layer / Storage Middleware      | 2.3、4.2、6.3.3     | 协议与工具接口连接 Gateway、SDK 和 MCP |
| 算力平台 / TEE                            | 3.3.3、6.2.3、7.2.1 | 受控处理结果关联执行环境和 Attestation   |
| Storage API / CLI / 部署接口              | 4、6、8             | 通过版本适配、参数映射和幂等迁移连接目标配置      |
| 经济模型与节点激励                             | 8.3               | 将参数化服务、证明和结算规则应用于状态负载       |

文档迁移表包含源路径、目标路径、适用版本和永久重定向规则。构建流程执行链接检查和示例验证，部署流程探测重定向、缓存刷新及目标内容摘要。历史示例保留版本标签并归入独立索引，当前入口始终使用匹配 Deployment Registry 的命令与配置。

## 9.3.3 技术扩展与架构记录

扩展方案通过版本化架构记录定义接口、策略和验证规则。下表给出各扩展域采用的机制及自动验证路径：

| 扩展域                   | 技术方案                                                          | 自动验证                          |
| --------------------- | ------------------------------------------------------------- | ----------------------------- |
| Agent DID 与身份连续性      | DID 绑定签名公钥和实例；换钥创建新实例和 DID；双签连续性记录或独立恢复声明关联历史；Owner 签发新委托     | 解析、控制证明、防重放、撤销、恢复凭据及新旧权限隔离    |
| ADP / ATIF 等 Trace 交换 | 适配器按外部版本映射事件、工具、结果和对象引用，保留原始格式引用并按策略裁剪敏感字段                    | Schema 映射、引用完整性、往返转换和敏感字段扫描   |
| Memory Engine         | 原始来源与状态对象作为可追溯记录，索引引用对象版本，候选经策略准入，删除事件传播到派生索引                 | 对象与索引一致性、准入拒绝、污染隔离和迁移恢复       |
| A2A Handoff           | Task / Artifact 绑定 Memory Pack、任务标识、接收者委托及双向回执，按幂等记录恢复        | 跨组织授权、包完整性、撤销竞态、部分失败和去重       |
| Attestation 信任        | 信任注册表限定发行者、声明类型、有效期和撤销规则，验证器按策略组合证据                           | 发行者链、签名、类型范围、有效期及撤销查询         |
| 受控计算                  | 按任务选择 TEE 或组织受控环境；ZKP 证明明确计算命题，FHE 处理适合其算子的加密计算；密钥释放绑定任务和环境策略 | 环境证明、镜像、用途、输入输出范围、资源预算及密钥释放条件 |
| 选择性资产化                | 来源许可、资产所有权、访问、训练与再分发分别建模，Owner 策略选择对象，交付按接收者封装                | 权利条件、许可范围、敏感扫描、支付与授权双门槛       |
| 节点经济与 Proof           | 小对象批处理、版本保留与存储分层连接订单；计量和证明关联结算；参数受预算与治理策略约束                   | 负载、恢复、挑战、虚假订单、释放上限与账本核对       |

架构记录包含方案版本、作用范围、约束、配置、验证和回退，采用以下格式。参数从对应架构与构建清单解析；校验器检查必填项、引用、Schema 和迁移用例，记录以签名及内容摘要归档。

```markdown
# ADR-<number>: <decision_title>

- record_state: active | superseded
- date: <date>
- responsibility_roles: <责任角色>
- architecture_version: <架构版本>
- configuration_refs: <策略、Schema、注册表与兼容性引用>
- validation_refs: <验证规则、作业与报告引用>

## Context
<业务问题、依赖、约束和风险>

## Design
<采用的机制、接口、数据流与责任边界>

## Configuration
<参数来源、类型范围、默认策略和校验规则>

## Security and privacy
<身份、权限、密钥、数据、经济与运行控制>

## Compatibility and migration
<Schema、API、合约、客户端与历史数据映射>

## Validation and rollback
<自动验证、停止条件、恢复点与回退规则>
```

架构记录被新版本替代时建立前后引用并保留历史签名。验证环境使用隔离数据和测试资产；接口进入构建清单前执行类型、依赖、安全策略及兼容性检查。运行配置始终绑定通过校验的架构记录、制品和注册表，形成可追踪的设计、配置与执行关系。
