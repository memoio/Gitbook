# 附录 B：技术规格与配置契约

## 附录 B：技术规格与配置契约

部署配置将身份、对象、权限、证据、支付和运行环境组合为可验证的服务契约。配置由可信签发者签名，声明作用域、版本、有效期和内容摘要；组件启动与配置切换均由加载器校验签名、依赖、接口和环境约束，并按校验结果装载或拒绝。

### B.1 核心技术规格与配置关系

| 标准与适配              | 每个适配器固定规范引用、接口版本、功能集合、传输、认证及字段映射                                                       | 启动时比对双方能力清单，契约检查覆盖序列化、鉴权、错误、重试和版本边界                                                                  | 4.2、7.3、8.2.2     |
| 网络与合约              | Deployment Registry 关联环境、chain ID、RPC、合约地址、ABI 摘要、代理与升级权限                              | 校验网络标识、地址格式、链上代码、ABI 与权限配置；读写入口使用匹配环境与合约配置                                                           | 6.2、8.1.2—8.1.3   |

身份、配置签名、数据加密、支付与审计使用相互区分的密钥用途和权限范围。组件只解析完成校验的配置，不把端点可达、支付成功或证据存在解释为资源授权或业务验收通过。

### B.2 配置版本、自动验证与回退

配置清单包括 `registry_version`、`environment`、`component_versions`、`api_versions`、`schema_versions`、`adapter_profiles`、`policy_refs`、`network_refs`、`key_refs`、`config_digest`、`valid_from`、`expires_at`、`issuer` 和 `signature`。每次配置变更生成新的不可变清单，组件记录使用的清单摘要，使请求、计量、回执和证明能够追溯到同一运行配置。

加载器按以下顺序执行：

{% stepper %}
{% step %}
### 校验来源与内容

读取受信端点的签名清单，验证签发者资格、摘要、签名、作用域和有效期。
{% endstep %}

{% step %}
### 解析依赖

将 API、Schema、SDK、适配器、策略和合约引用解析为固定版本，检查引用闭合、类型、允许范围及环境一致性。
{% endstep %}

{% step %}
### 核验环境

验证服务身份、chain ID、合约代码与 ABI 对应关系、密钥用途、解密位置、后端能力和额度配置。
{% endstep %}

{% step %}
### 执行契约检查

按验证配置检查对象往返、授权拒绝、撤销、幂等、支付对账、证据查询和恢复路径。
{% endstep %}

{% step %}
### 切换配置

对有效清单执行原子切换；请求绑定处理开始时的配置摘要，跨步骤复核安全相关的撤销和策略变化。
{% endstep %}

{% step %}
### 处理异常

失败清单保持隔离；回退只选择仍处于有效期、符合安全约束的配置。没有合格配置时拒绝相应请求，保留错误、事件和已有对象版本。
{% endstep %}
{% endstepper %}

兼容性变更通过版本窗口与转换器处理。涉及 DID、授权、密钥、对象、支付或证明语义的变更分别定义输入兼容条件、转换映射、验收规则、回退点和外部副作用处理；历史签名与对象版本保持原始含义。运行指标以环境、负载、测量方法、时间范围和配置摘要组织，指标目标与实际观测值分别记录。
